# 报告体例（Report Format）

本文件是输出层的契约：**读者先看到结论，再看支撑结论的少数判断，最后才看到证据明细**。
产品口径（有什么、怎么评分）见 `docs/PRD.md`；运行方式见 `docs/OPERATIONS.md`。

## 为什么改成这个体例

旧版日报是"按通道罗列 + 每条附全部事实/推断/缺口"，150 条历史一次渲染后读者拿不到任何
可执行的判断。专业咨询机构的报告结构（MBB / Big Four 通行做法）解决的是同一个问题：

- **金字塔原理**（Barbara Minto，前 McKinsey）：结论先行，上层概括下层，同层 MECE。
- **执行摘要**：一句话治理信息（governing message）+ 3–5 条关键判断，每条是"完整、有证据"
  的断言，不是主题标签。
- **行动标题**：每个标题都是完整句子，只读标题就能读出故事线。
- **影响与行动分离**：事实 → 影响 → 建议动作 → 完成标准，四层不混写。
- **Basis of preparation**：方法、覆盖、局限、版本单独成节，读者知道结论的边界。

## 固定结构

| 节 | 内容 | 硬性要求 |
|---|---|---|
| 页眉 | 编号、生成时间、数据基础（获取/分析/覆盖率/入选） | 覆盖率必须在正文出现 |
| 一、执行摘要（核心判断） | 一句话治理信息 + 管理注记 | 不完整运行先说不完整 |
| 二、关键判断 | 3–5 条 KJ，每条含 判断/依据/影响/置信度 | 按编辑优先级再按分数排序 |
| 三、建议行动 | 分析给出的 action，含完成标准与依据 | 不新造动作；没有就明说没有 |
| 四、待验证假设 | 分析支持但未核实的推断 | 必须标"不作为结论" |
| 五、风险与反证 | 单一来源、未定位引文、证据缺口 | 没有反证时要说明"不等于证据可靠" |
| 六、监测清单 | 观察项 + 触发条件 + 当前评分 | 最多 6 条，其余进附录 |
| 七、证据与方法 | 漏斗、通道分布、证据强度、口径、模型/提示词/规则、局限 | 版本与覆盖率不可省略 |
| 八、附录 A | 条目明细：事实/推断/缺口/行动/来源 | 可追溯到引文位置 |
| 九、附录 B | 未纳入分发、已过滤、弱信号 | 配额不改变条目本身的判断 |
| 十、附录 C | 来源贡献、数据质量、数据冲突、来源审计、评分规则 | 冲突只记录，不判定对错 |

## 邮件版与完整版

日报有两个版本，共用同一份条目、同一套门禁，区别只在输出范围：

| 版本 | 内容 | 用途 |
|---|---|---|
| 邮件版 | 页眉 + 第一至七节 + 附录说明 | 每日投递；约 9 KB，不含逐条明细 |
| 完整版 | 邮件版全部内容 + 第八至十节附录 | 本地 `reports/latest-digest.{txt,html}`、归档与管理台 |

- 邮件版不发送附录 A/B/C。附录说明保留**计数**（条目明细、未纳入分发、已过滤、来源审计
  问题），因此被排除的条目不会静默消失。
- 附录按 `report_hash` 写入 SQLite `report_sections` 表（`email_brief`、`appendix_a`、
  `appendix_b`、`appendix_c`），同时随归档保存 `*.email.txt` 与 `*.email.html`。
- 两版都经过 `_validate_report`：覆盖率不足时两个版本都必须出现“覆盖率”。
- 重发失败地址读取 `latest-digest-email.{txt,html}`，不会把附录重新发出去。

## 执行层如何选条目

格式解决不了"没有重点"：**哪些条目能进入关键判断**才是重点的来源。

1. **商业含义是入场券**，只看结构化字段：`signal_type` 属于需求/痛点/部署障碍/产品缺口，
   或 `buyer_payment_evidence` 为明确预算/已有采购，或 `pain_point` 非 unknown。
   不看 `commercial_signal` 的自由文本——每条"无商业机会信号"都含"商业"二字，关键词判定
   会把游戏评测和统计预告页提拔成关键判断（2026-11-08 实测）。
2. **排序依次为**：可执行性（act > decide > investigate > monitor）→ 通道（B 机会 → A 变化
   → C 技术）→ 编辑优先级 → 信号分。编辑优先级高但不改变行动的条目不应领衔。
3. **没进执行层的条目必须被点名**："另有 N 条入选条目没有可识别的商业信号……保留在附录 A"，
   不允许静默消失。
4. **建议行动只来自执行层条目**，每行以 `KJ1` 引用它所服务的判断，不重复整句标题。
5. 若执行层为空，摘要直接说"本期入选条目的分析结论均为无商业信号"，不设关键判断。

## 写作规则

1. **结论先行**：`decision_headline` 必须是可执行的一句话；失败、覆盖不足、熔断先于任何结论。
2. **一条判断只回答一个问题**：这条信息是否改变我们的行动。
3. **证据分层**：`E2 一手来源原文已核对` / `E1 摘要引文已定位` / `E0` 三档，禁止混写；
   未定位引文永远不进"事实"层。
4. **置信度可下调不可上调**：单一来源时，"高"置信度降级为"中（单一来源，未独立佐证）"。
5. **影响只用品类字段**：买方类型、付费证据、技术成熟度等已分类字段，不新造市场判断。
6. **行动不新造**：只渲染分析产出的 `actions[]`；没有就写"维持监测，不启动新动作"。
7. **数字有出处**：所有计数来自本次渲染的条目；附录 C 给出分母口径。

## 契约与门禁

- `cli._validate_report` 要求：主题非空、正文含"执行摘要"、HTML 有文档骨架、覆盖率 <1 时
  正文与 HTML 都必须出现"覆盖率"、状态计数必须与条目重算一致。
- `tests/test_digest.py`、`tests/test_html.py` 锁定上面每一节的存在与关键语义：
  失败可见、引文分层、欠覆盖披露、配额不改判断、单一来源不冒充交叉验证。
- 修改体例时同步本文件与上述测试；不为通过测试而删掉语义断言。

## 语言

面向人的字段一律简体中文（`facts[].text`、`inferences[].text`、`gaps[]`、`actions[]`、
`claims[].statement`、`pain_point`、`target_customer`、`commercial_signal`）。
唯一例外是逐字引文 `facts[].quote`：保持原文语言，不得翻译或改写。该规则由
`prompts/analyst_v8.md` 的 Language 节约束。
