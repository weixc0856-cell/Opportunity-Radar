# 报告体例（Report Format）

本文件是输出层的契约：**读者先看到结论，再看支撑结论的少数判断，最后才看到证据明细**。
产品口径（有什么、怎么评分）见 `docs/PRD.md`；运行方式见 `docs/OPERATIONS.md`。

## 为什么改成这个体例

旧版日报是"按通道罗列 + 每条附全部事实/推断/缺口"，150 条历史一次渲染后读者拿不到任何
可执行的判断。专业咨询机构的报告结构（MBB / Big Four 通行做法）解决的是同一个问题：

- **金字塔原理**（Barbara Minto，前 McKinsey）：结论先行，上层概括下层，同层 MECE。
- **执行摘要**：一句话治理信息（governing message）+ 3–5 条关键判断，每条是"完整、有证据"
  的断言，不是主题标签。
- **行动标题**：每个标题都是完整句子，只读标题就能读出故事线。
- **影响与行动分离**：事实 → 影响 → 建议动作 → 完成标准，四层不混写。
- **Basis of preparation**：方法、覆盖、局限、版本单独成节，读者知道结论的边界。

## 固定结构

日报自 2026-11-21 起重定位为**个人情报站**：主体是政策/媒体/市场整合与长线关注，服务长线投资与
个人低成本创业；原"商业机会/买方/就绪度/验证"层**降为附录 D** 保留，只有经核实后才用于下游
投资/创业建议，不再领衔。

| 节 | 内容 | 硬性要求 |
|---|---|---|
| 页眉 | 编号、生成时间、数据基础（获取/分析/覆盖率/入选） | 覆盖率必须在正文出现 |
| 一、执行摘要（情报主线） | 情报治理信息 + 角度注记 + 用途 + 长线关注预览 | 不完整运行先说不完整；没有可跟踪主题要直说 |
| 二、情报整合与长线关注 | 按情报主线与事件分组；每主题给官方/媒体/市场角度、对照情况、证据、核实状态、长线触发 | 单一Angle标"待独立对照"；未核实不作为投入依据 |
| 三、证据与方法 | 漏斗、通道分布、情报主线、证据强度、就绪度、独立性、口径、模型/提示词/规则、局限 | 版本与覆盖率不可省略 |
| 四、附录 D · 机会与验证 | 下游机会层：关键判断/建议行动与验证台账/待验证假设/风险与反证/监测清单 | 标明"经核实后才用于投资/创业"；不新造动作 |
| 五、附录 A | 条目明细：事实/推断/缺口/行动/来源 | 可追溯到引文位置 |
| 六、附录 B | 未纳入分发、已过滤、弱信号 | 配额不改变条目本身的判断 |
| 七、附录 C | 来源贡献、数据质量、数据冲突、来源审计、评分规则 | 冲突只记录，不判定对错 |

附录 D 内部子标题不带节号（关键判断/建议行动与验证台账/待验证假设/风险与反证/监测清单），
语义与旧版一致：证据分层、单一来源不冒充独立佐证、行动不新造、停止条件与完成标准保留。

## 邮件版与完整版

日报有两个版本，共用同一份条目、同一套门禁，区别只在输出范围：

| 版本 | 内容 | 用途 |
|---|---|---|
| 邮件版 | 页眉 + 第一至三节 + 附录说明 | 每日投递；不含机会层与逐条明细 |
| 完整版 | 邮件版全部内容 + 附录 D/A/B/C | 本地 `reports/latest-digest.{txt,html}`、归档与管理台 |

- 邮件版不发送附录 D/A/B/C。附录说明保留**计数**（条目明细、未纳入分发、已过滤、来源审计
  问题），因此被排除的条目不会静默消失。
- 附录按 `report_hash` 写入 SQLite `report_sections` 表（`email_brief`、`appendix_d`、
  `appendix_a`、`appendix_b`、`appendix_c`），同时随归档保存 `*.email.txt` 与 `*.email.html`。
- 两版都经过 `_validate_report`：覆盖率不足时两个版本都必须出现“覆盖率”。
- 重发失败地址读取 `latest-digest-email.{txt,html}`，不会把附录重新发出去。
- **HTML 渲染分两套**（2026-11-21）：完整版（本地/管理台）保留咨询报告版式——CSS grid/flex
  排版与 SVG 图表，只在真实浏览器里渲染。邮件版改用纯内联样式的 `<table>` 重建同一份内容，
  不用 `<style>` 块、不用 grid/flex、不用 SVG：多数邮箱客户端（163/QQ、Outlook、Gmail）会剥离
  或忽略这三者，导致旧邮件版在收件箱里退化成没有标签、挤成一行的文字（如漏斗与通道分布）。
  两版内容、节序与门禁完全一致，只有呈现层不同；`tests/test_html.py::EmailClientCompatibilityTests`
  锁定邮件版不含 `<svg`/`<style`/grid/flex，且通道等固定分类名不再被截断。

## 决策就绪度（对标咨询机构的核心门）

日报不再把"编辑优先级高"或"分数高"当作可推荐。每条入选条目先算一个确定性的就绪度：

| 就绪度 | 条件 | 报告中的用法 |
|---|---|---|
| 决策级 | `explicit_budget`（明确预算）+ E2 + 可定位事实 + `act/decide` + 买方确认或多来源 | 可进入投入/不投入决策 |
| 验证级 | 商业信号 + E1/E2 + 可定位事实 +（`act/decide/investigate` 或 `pain_evidence=repeated` 或付费弱证据） | 限时验证，不做投入 |
| 观察级 | 其余 | 只监测，不进关键判断层 |

关键取舍：`existing_purchase` 只证明"预算存在"，不能证明"预算会给我们"，因此**不能**单独支撑决策级。
单一论坛帖只有在同类痛点重复出现、且有可定位证据时，才进入验证级；否则只作为观察线索点名。
这一层只使用结构化字段，不读取模型自由文本。

## 对标四大/麦肯锡：已对齐与未覆盖

| 咨询机构要求 | 本报告做法 | 状态 |
|---|---|---|
| 结论先行 / 治理信息 | 执行摘要第一句是决策陈述，先说不完整运行与无决策级机会 | 已对齐 |
| 行动标题 | `action_title`（v9 模型字段）优先，回退到摘要首句；不在从句中间加省略号 | 已对齐 |
| So what / 影响 | 每条判断有"影响（so what）"，区分决策级/验证级/观察级 | 已对齐 |
| 证据可追溯 | 事实/引文定位、证据等级、单一来源标注、附录 A 逐条追溯 | 已对齐 |
| 决策请求与选项 | 决策请求 + A/B/C 选项 + 默认不投入 | 已对齐 |
| 行动台账 | 完成标准、建议时限、负责人（待指派）、依据 KJ | 已对齐 |
| 风险登记表 | 风险/触发条件/影响/应对；含停止条件 | 已对齐 |
| 验证台账 | 就绪度/已量化/关键缺口/关闭方式/停止条件 | 已对齐 |
| 验证记录闭环 | `--validation-record` 追加入库；报告显示访谈/定价/买方/决策结果 | 已对齐 |
| 量化（市场规模、收入、ROI） | 只打印文中数字，明确标"不是市场规模或收入预测"；缺口单列 | **未覆盖**（缺外部数据） |
| 竞品/替代方案对标 | 未做；在"外部对标"局限中明示 | **未覆盖**（缺外部数据） |
| 一手访谈/专家访谈 | 提供 `--validation-record` 记录入口；访谈本身仍需人工执行 | **部分覆盖**（记录已对齐，执行未覆盖） |
| 财务模型/敏感性分析 | 未做；没有预算、价格、客户数就无法可靠建模 | **未覆盖**（缺输入） |

结论：结构、证据纪律与决策门已对齐；**量化与外部对标不能靠现有 RSS 供给生成**，报告选择
明示缺口而不是编造数字。补齐这些需要接入市场/财务数据源或人工研究，属于下一阶段。

## 执行层如何选条目

格式解决不了"没有重点"：**哪些条目能进入关键判断**才是重点的来源。

1. **商业含义是入场券**，只看结构化字段：`signal_type` 属于需求/痛点/部署障碍/产品缺口，
   或 `buyer_payment_evidence` 为明确预算/已有采购，或 `pain_point` 非 unknown。
   不看 `commercial_signal` 的自由文本——每条"无商业机会信号"都含"商业"二字，关键词判定
   会把游戏评测和统计预告页提拔成关键判断（2026-11-08 实测）。
2. **排序依次为**：可执行性（act > decide > investigate > monitor）→ 通道（B 机会 → A 变化
   → C 技术）→ 编辑优先级 → 信号分。编辑优先级高但不改变行动的条目不应领衔。
3. **没进执行层的条目必须被点名**："另有 N 条入选条目没有可识别的商业信号……保留在附录 A"，
   不允许静默消失。
4. **建议行动只来自执行层条目**，每行以 `KJ1` 引用它所服务的判断，不重复整句标题。
5. 若执行层为空，摘要直接说"本期入选条目的分析结论均为无商业信号"，不设关键判断。

## 写作规则

1. **结论先行**：`decision_headline` 必须是可执行的一句话；失败、覆盖不足、熔断先于任何结论。
2. **一条判断只回答一个问题**：这条信息是否改变我们的行动。
3. **证据分层**：`E2 一手来源原文已核对` / `E1 摘要引文已定位` / `E0` 三档，禁止混写；
   未定位引文永远不进"事实"层。
4. **置信度可下调不可上调**：单一来源时，"高"置信度降级为"中（单一来源，未独立佐证）"。
5. **影响只用品类字段**：买方类型、付费证据、技术成熟度等已分类字段，不新造市场判断。
6. **行动不新造**：只渲染分析产出的 `actions[]`；没有就写"维持监测，不启动新动作"。
7. **数字有出处**：所有计数来自本次渲染的条目；附录 C 给出分母口径。
8. **不重复同一证据**：KJ 的"依据"已给出证据等级与可定位事实数，"就绪度"只写绑定原因
   （可执行性、重复痛点、付费弱证据），不再复述等级与条数。
9. **监测清单的触发条件是条件，不是动作**：用尚未确认的关键缺口（`gaps[].missing`）表述
   "一旦确认……"，不把"如何补齐"（`how_to_close`，一个动作）冒充触发条件。
10. **固定分类名不截断**：通道、情报主线等枚举标签整词显示；只有自由文本（标题、来源名）
    才按可用宽度截断，且不在从句中间硬切。

## 契约与门禁

- `cli._validate_report` 要求：主题非空、正文含"执行摘要"、HTML 有文档骨架、覆盖率 <1 时
  正文与 HTML 都必须出现"覆盖率"、状态计数必须与条目重算一致。
- `tests/test_digest.py`、`tests/test_html.py` 锁定上面每一节的存在与关键语义：
  失败可见、引文分层、欠覆盖披露、配额不改判断、单一来源不冒充交叉验证。
- 修改体例时同步本文件与上述测试；不为通过测试而删掉语义断言。

## 周期报告（周 / 月 / 年，对标专业机构）

`period_report.py` 从事件/证据/主张图按日期窗口重建周期报告，不是日报拼接：

- **周报**（7 天）、**月报**（30 天）、**年报**（滚动 365 天）。`--period weekly|monthly|yearly`
  单独生成；`--period auto` 按 6/29/364 天节奏补跑（以最后一份报告时间计，漏跑不静默跳过）。
- **回归核验**（月/年为核心）：对窗口前已存在的基线主张，用窗口内新增证据/核验/冲突/重述
  重新分类为 已确认 / 被反证 / 仍开放 / 数据不足，逐条给依据。单一来源族不算独立佐证；
  数值重述差 >1% 记被反证。基线为空时明说"没有可回归的历史主张"，不编造。
- **情报主线与来源角度**聚合（官方/媒体/市场/资本）+ 分母口径 + 缺口（无证据主张/未核实/
  分析失败/覆盖率/门禁）+ 规则版本。数据更清晰完整，但缺外部测算仍标"未测量"。
- 年报口径为滚动 365 天年度窗口，做全年回归核验；随时间积累基线后才有跨期确认/反证。

## 语言

面向人的字段一律简体中文（`facts[].text`、`inferences[].text`、`gaps[]`、`actions[]`、
`claims[].statement`、`pain_point`、`target_customer`、`commercial_signal`）。
唯一例外是逐字引文 `facts[].quote`：保持原文语言，不得翻译或改写。该规则由
`prompts/analyst_v9.md` 的 Language 节约束。
