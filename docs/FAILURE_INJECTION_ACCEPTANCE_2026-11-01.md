## 1. 目的

条件 3 要回答一个问题：**当来源不可用、返回异常或数据变形时，系统会不会把失败伪装成"没有情报"或"数值为 0"。**

因此本条件的验收对象不是"能否取到数据"，而是：

1. 每类失败都能被归入明确的 `error_class`，不存在 unclassified；
2. 失败不产生观测值（`observation`），空集不写成 0；
3. 一个来源失败不牵连另一个来源；
4. 失败在运行记录与报告中可见，且措辞不外溢为"无数据"结论。

---

## 2. 方法：本地模拟优先

| 手段 | 规则 |
|---|---|
| 本地模拟响应 | **默认手段**。所有 401/403/429/5xx/超时/空集/字段变化/分页截断都在本地夹具上验证 |
| 真实服务 | 只允许验证**已经观察到**的行为（EIA 的 403 无 key、404 错误 route、200 空集、分页 warnings、年度缺 2026） |
| 禁止 | 对 EIA 或 SEC 发起压力测试、并发打点、用错误 key 反复试探、通过更换 User-Agent 规避 403 |
| 频率 | 真实请求沿用已记录的节奏（≥0.35 s/请求），单轮新增真实请求数为 0 时优先保持为 0 |

理由：限流与 5xx 的代价由对方承担，而这三类行为在本地夹具上与真实响应等价；真实服务能补充的信息只有"实际错误体长什么样"，不值得为此制造流量。

---

## 3. 失败分类

沿用设计文档 §6 的七类，并补两类数据形态问题：

| `error_class` | 含义 | 典型触发 |
|---|---|---|
| `auth` | key 缺失/无效、UA 被拒 | 401、403 |
| `rate_limit` | 超出配额 | 429 |
| `not_found` | route、CIK、tag 不存在 | 404 |
| `server` | 对方服务端故障 | 5xx |
| `timeout` | 连接或读取超时 | socket timeout |
| `schema` | 响应结构不符合契约 | 缺 total、缺 units、类型错误 |
| `truncation` | 分页累计行数 < `total` | 分页重试耗尽 |
| `empty_result` | 查询合法但返回空集，或查询本身无效 | 200 + `total:"0"` |
| `rights` | 许可或再分发边界不满足 | 未确认的第三方内容 |

`empty_result` 与 `not_found` 必须分开：前者说明"这条查询不成立"，后者说明"这个对象不存在"。
EIA 的无效 facet 走的是 `empty_result`（HTTP 200），不是 `not_found`。

### 4.3 权利类

| ID | 场景 | 来源 | HTTP | 期望 `error_class` | 期望动作 | 输出行数 |
|---|---|---|---|---|---|---|
| RIGHTS-01 | 许可状态未核实；再分发不允许，商业使用未知 | 合成 | — | `rights` | 隔离记录，不入库 | 0 |

该样本不是 HTTP 响应，而是一条**合成**的权利判定记录（`fixture_kind: rights_record`），
显式区分 `commercial_use` 与 `redistribution` 两项权限，并携带 `license_status: not_verified` 与缺失的 `terms_checked_at`。
它覆盖两类权利问题：**权利信息缺失**（无许可声明、条款页需登录）与**授权范围不足**（再分发明确不允许）。
验收要求：记录被隔离而不是入库；两项权限不得合并成一个"是否可用"的布尔值；许可未确认前不得作为可用证据。

## 5. 验收判据

### 5.1 逐样本判据

每个夹具必须同时满足：

1. 输出行数等于上表的"期望输出行数"；
2. `error_class` 与上表一致，或为 `null`（表示不算失败）；
3. 当期望输出为 0 时，**不得**产生任何 `observation` 记录；
4. 当期望标记为 `schema_drift` / `observed_change` / `no_facts` / `ytd_derived` 时，标记必须出现在 `quality_flags`；
5. 运行记录里必须留下该样本的可追溯条目（fixture_id、error_class、时间）。

### 5.2 跨样本判据

| 编号 | 判据 |
|---|---|
| A1 | 任一夹具失败时，另一来源的处理不受影响（逐来源隔离） |
| A2 | `EIA-13` + `EIA-14` 连续处理后，版本 1 仍存在，未被覆盖 |
| A3 | `EIA-08` 的 `warnings` 不被当作截断；完整性由「累计行数 == total」判定 |
| A4 | `EIA-07` 与 `EIA-12` 的失败原因可区分（查询无效 vs 数据不完整） |
| A5 | `SEC-08` 与 `SEC-09` 处理后，同一 `(cik, tag, unit, start, end)` 只有一条被标记为选中值 |
| A6 | 所有失败均不产生"数值为 0"或"该来源无数据"的报告语句 |
| A7 | 报告中该来源的缺失原因可读且具体（`auth` / `rate_limit` / `truncation` 等），不是笼统的"失败" |

### 5.3 不属于本条件的部分

发布门禁（全失败 HOLD、部分失败限制性发布）属于 **R0** 的范围。本条件只验证连接器层：
来源失败是否被正确分类、是否正确停止、是否污染数据。
R0 未启动，本文件不定义、也不实现发布层行为。
