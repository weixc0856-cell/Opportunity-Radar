## 1. 决策背景

`IMPLEMENTATION_PLAN.md` §13.4 原计划把新来源接入 `cli.py` 并保持 `articles` 入库契约，
与 §13.5 边界 1 直接冲突。**2026-11-01 决定：第一阶段采用独立存储方案，废止原接入方式。**
§13.4 已同步改写，冲突已消除。

理由不只是文档一致性：企业财务事实（SEC XBRL fact）与能源时间序列（EIA observation）
不是新闻文章。把它们塞进 `articles` 会强制进入标题哈希去重、来源独立性与编辑评分体系，
既改变现有日报链路，也无法表达 fact / observation 的结构差异。

---

## 2. 批准范围

| 项目 | 决策 | 说明 |
|---|---|---|
| SEC EDGAR | **批准进入第一阶段** | 限定在条件 1 样本矩阵覆盖的公司、指标与标签映射 |
| EIA | **批准进入第一阶段** | 限定在条件 2 验证过的单一 route / 单一指标 / 单一 facet 组合 |
| 运行入口 | **独立 module、独立进程** | 不被 `cli.main()` 调用 |
| 数据存储 | **独立 SQLite 文件** | 不写 `data/opportunity_radar.sqlite3` |
| 数据表 | **独立 schema / 表** | 不写 `articles`、`analyses`、`analysis_history`、`analysis_sections`、`runs` |
| 配置 | **独立配置项** | 不与 `freshrss_feed_id` 混用 |
| 运行状态 | **独立记录** | 不写现有 `runs` 表 |
| RSS 日报 | **不接入、不改变** | `cli.py`、`digest.py`、`render_html.py` 不改动 |
| LLM 分析与评分 | **默认不接入、不改变** | 新来源数据不进入模型调用 |
| 证据门槛与评分规则 | **不修改** | `evidence.py`、`scoring.py`、`config/scoring.toml` 保持不动 |
| 运行验证 | **实施阶段执行** | 故障注入、并发、超时测试纳入第一阶段验收 |

第一阶段的工作范围只有四件事：

1. **数据获取**：按限定范围调用 SEC / EIA 接口，保存原始响应快照。
2. **规范化**：字段映射、单位、期间、外部 ID；原始值与派生值分开。
3. **存储**：写入独立 SQLite 文件；快照不覆盖，按内容哈希去重。
4. **质量验证**：对账、空集识别、分页完整性、修订观察。

---

## 3. 明确不批准

以下事项**不在**本授权范围内，实施中不得自行扩大：

1. 让 SEC/EIA 数据进入现有 LLM 分析流程（`analyzer.py` / `cli.py` 分析循环）。
2. 让新来源数据参与现有评分或证据门槛判定。
3. 让新来源数据出现在 `digest` / `render_html` 的任何日报路径，包括 `--render-only`。
4. 修改 `cli.py`、`store.py`、`digest.py`、`render_html.py`、`evidence.py`、`scoring.py`、
   `config/scoring.toml` 或 `config/sources.local.csv` 的既有语义。
5. 向现有业务表写入任何 SEC/EIA 记录。
6. 扩大 EIA 数据范围：其他 route、其他 `data` 字段、`ALL`/`COL`/`sectorid=98`、州级与 Census Region。
7. 扩大 SEC 范围到条件 1 样本矩阵之外的公司或自定义 taxonomy / 维度化事实解析。
8. 启动 R0（运行可靠性与发布门禁），R0 仍为独立阶段、独立审批。
9. 接入 Ember 或其他 S0 未冻结的来源。
10. 修改任何现有定时任务。

## 4. 第一阶段验收要求

实施完成不等于验收通过。以下必须在实施阶段实际执行并留证：

| # | 验收项 | 判据 |
|---|---|---|
| 1 | 独立进程可运行 | 自有入口，与 `python -m opportunity_radar.cli` 互不影响 |
| 2 | 独立存储生效 | 运行时现有 `data/opportunity_radar.sqlite3` 的 mtime 与表行数不变 |
| 3 | 数据对账 | EIA 2024 / 2025 年度值与 EPM Table 1.1 取整后一致；SEC 与申报原文可回溯 |
| 4 | 失败注入 | 条件 3 的 25 个样本在连接器上执行，A1–A7 由 `NOT_VERIFIED` 转为有结论 |
| 5 | 并发与超时 | 与日报任务同时运行时的锁行为、超时传播范围有实测记录 |
| 6 | 现有链路回归 | 现有 423 项单元测试通过；`--dry-run` 日报与实施前一致 |
| 7 | 条件 5 的 B 项 | 故障完全隔离由 `NOT_VERIFIED` 转为可判定（PASS 或 FAIL） |

第 4–7 项是条件 5 的 B 项与实施前条件 3 的 A1–A7 的解除路径：**样本齐备不等于行为已验证**。
