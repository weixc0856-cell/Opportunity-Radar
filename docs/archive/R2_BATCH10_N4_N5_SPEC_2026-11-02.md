## 1. 范围与边界

本批在已合并的 N0–N3 之上实现：

- **N4：数值标准化**（`opportunity_radar/n4_normalization.py`，`n4-v1`）
- **N5：完整性门禁与 r2-v4 影子 Claim 组装**（`opportunity_radar/n5_assembly.py`，`n5-v1`）

N4/N5 都是确定性程序，不调用模型；不修改生产 Claim 表、v6/v7 提示词、评分、R0 门禁、
日报与邮件；不启用 v7；不申请 G6；不引入新框架。

N4 不重新识别主体、不推断关系、不补造 baseline/period/comparison。
N5 不调用模型补全信息、不猜主体/指标/期间/比较口径、不用标题代替证据、不降低完整性要求。

## 2. N4 契约

### 输入

N0 文档、N1 原子与表达组、N2 候选解释、N3 关系。

### 输出

```json
{
  "node": "N4", "node_version": "n4-v1", "document_id": "...",
  "input_hash": "...", "output_hash": "...", "ruleset": "...", "units_version": "...",
  "normalized_records": [
    {"record_id": "n4_...", "candidate_id": "...", "candidate_type": "currency",
     "relationship_id": "...", "relationship_type": "change",
     "value": 92.8, "unit": "USD", "scale": "billion", "currency": "USD",
     "unit_family": "currency", "unit_string": "USD billion",
     "raw_value": "92.8", "raw_unit": "USD", "raw_scale": "billion",
     "comparison": "unknown", "seasonality": "unknown", "revision": "unknown",
     "direction": "increase", "period": "", "period_raw": "",
     "period_candidate_ids": [], "baseline": [], "baseline_candidate_ids": [],
     "denominator": "", "denominator_candidate_ids": [],
     "source_candidate_ids": ["..."], "source_relationship_ids": ["..."],
     "evidence_quote": "...", "evidence_start": 1, "evidence_end": 20,
     "evidence_field": "body", "interpretation_quote": "...",
     "interpretation_start": 1, "interpretation_end": 20, "interpretation_field": "body",
     "source": "n2|n3", "status": "normalized", "reason": "", "deviations": []}
  ],
  "statistics": {}, "status": "success|partial|failed", "seconds": 0.0
}
```

`status`：`normalized` / `partially_normalized` / `unsupported_unit` / `ambiguous_numeric` /
`missing_semantics` / `invalid_relationship` / `unresolved`。

### 规则

- `value` 是原文数值（92.8），不乘数量级；`scale` 单独保存（billion）；`currency` 单独保存（USD）。
- `unit_string` 供 r2-v4 使用：币种在前（`USD billion`），物理单位数量级在前（`million vehicles`）。
- `%` 与 `pp` 不同；`2 percentage points` 不得变成 percent。
- 无单位数字保留空单位，不赋予经济单位。
- 未知单位（如 duration/count 之外的词）→ `unsupported_unit`。
- 括号负数标记 `parenthesized_sign_not_inferred`，不擅自取负；科学计数法标记。
- N3 关系类型仅 `level/change/comparison/revision/share/rate` 可组装；`range/unknown` → `invalid_relationship`。
- N3 缺失 period/baseline 时保持空，记 `period_missing`/`baseline_missing`；change 缺 period、
  comparison/revision 缺 baseline → `partially_normalized`。
- `comparison=unknown` 记 `comparison_unknown`，不推断同比/环比。
- 每个 N2 `claim_value` 若无 N3 数值关系 → `missing_semantics` 记录，不消失。
- 相同输入、规则版本、单位版本产生相同记录与 ID；时间/重试不入哈希。

## 3. N5 契约

### 输入

N0、N1、N2、N3、N4。

### 输出

```json
{
  "node": "N5", "node_version": "n5-v1", "document_id": "...",
  "input_hash": "...", "output_hash": "...", "ruleset": "...",
  "contract_version": "r2-v4", "contract_hash": "...",
  "claims": [], "candidate_dispositions": [], "rejected_items": [],
  "unresolved_items": [], "coverage_statistics": {}, "contract_validation": {},
  "duplicates": [], "status": "success|partial|blocked|failed", "seconds": 0.0
}
```

每个 Claim 使用 `claim_contract.normalize` 的 r2-v4 字段；额外保留 `claim_id`、`status`、
`deviations`、`trace`（candidate/relationship/n4 record/证据定位/N2 subject 与 predicate）。
Claim 不由模型生成，也不写入生产表。

### 候选处置

每个 N1 原子恰好一个处置：

- `claim_accepted`（含 claim_ids）
- `context_only`
- `non_claim`
- `ambiguous`
- `unresolved`
- `relationship_unassigned`
- `normalization_failed`（含 unsupported_unit 等）
- `rejected`（含 contract_invalid / title_only_evidence / invalid_relationship）
- `used_as_context`（claim_value 仅作为 baseline/period 使用）

`coverage_complete` 要求处置数与 N1 候选数相等且 ID 唯一。Claim 数量不是成功指标。

### 组装与拒绝

- subject/predicate/kind 来自 N2；value/unit/scale/currency 来自 N4；关系/方向/比较/期间/
  baseline 来自 N3，只使用明确提供的信息。
- 证据必须能在 N0 原文定位；优先体文本，标题单独证据 → `title_only_evidence` 拒绝。
- 缺少 subject/predicate、value 非数值、单位/币种未知、期间格式非法、证据缺失 → 拒绝。
- 重复 Claim（同 subject/predicate/kind/value/unit/scale/currency/period/comparison/关系类型）
  只保留一条，其余记 `duplicate_claim`。
- 契约校验：把所有 payload 交给 `claim_contract.parse_claims`，输出 r2-v4 Claim；
  `claims_valid == claims_checked` 才算通过。
- status：N2 未成功 → `blocked`；覆盖不完整 → `failed`；所有候选为 claim_accepted/
  context_only/non_claim/used_as_context 且 N4 `success` → `success`；否则 `partial`。

## 4. 缓存与留存

哈希、`units.py` 源码哈希；N5 输入哈希包含 N0–N4 稳定哈希、N5 版本、r2-v4 版本与契约源码
哈希、规则源码哈希。执行时间/耗时/重试次数不进入哈希；失败运行不占成功键。

## 6. 验收

- 使用已留存的 BEA Personal Income、BEA International Trade 的 N2/N3 结果，端到端运行 N4/N5。
- 固定夹具 GDP/Intel/Obamacare/边界样本若没有 N2/N3 留存，N4/N5 记录 missing，不调用模型。
- 重点：`$54.5 billion` 不继承 monthly_rate；`0.2 percent at a monthly rate` 保留 monthly_rate；
  `0.5 percent` 不被解释为月度率；`3.8 percent` 不被解释为年度率；`$92.8bn` 等数值/数量级/币种正确；
  N3 未建立的 baseline/period 不由 N4/N5 补造；N2/N3 partial 时保留合格 Claim 并列出未处理项。
- 测试：N4 金额/数量级/币种、百分比与百分点、正负数/小数/范围、无单位、未知单位、unknown 关系、
  缺失期间/基准、稳定 ID；N5 r2-v4 完整性、证据定位、候选完整处置、partial、context/non_claim、
  unresolved、重复防护、谱系、缓存失效、空候选/失败。
- 全量测试必须通过；不得把固定夹具结果表述为真实语料通过率，不得把影子 Claim 表述为已核实事实。

## 7. 已批准的最小 units.py 变更

`5 million vehicles` 是规格要求的 N4 案例。`units.py` 原先没有 count/duration 单位族，
N5 走 r2-v4 会误报 `unknown_unit`。本批只做追加式补充：把 N1 已分类的 count/duration 名词
加入 `UNIT_FAMILY`，不修改任何既有单位、换算或核验规则，不引入跨族换算。
