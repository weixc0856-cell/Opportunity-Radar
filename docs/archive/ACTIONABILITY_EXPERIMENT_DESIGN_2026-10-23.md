# Actionability 离线字段试验：设计与字段定义（2026-10-23）

> 状态：已完成（2026-10-23）。本文件固定了字段语义、判定口径与评估规则；结果见
> `docs/ACTIONABILITY_EXPERIMENT_RESULTS_2026-10-23.md`。
> **不改变**评分权重、证据门槛、A/B/C 分流、priority/watch/filtered 判定或 `source_cap`。

## 一、字段定义

`actionability` 回答的是"读者读完能做什么"，是五级**有序**枚举：

| 值 | 含义 | 典型例子 |
|---|---|---|
| `none` | 纯信息，没有合理的下一步 | 娱乐新闻、与业务无关的事件 |
| `monitor` | 值得跟踪，但现在没有具体动作 | 例行统计发布、厂商产品稿 |
| `investigate` | 有明确的核查动作 | 核对原始文件、查数据、复现问题、联系来源 |
| `decide` | 能直接支持一个决策 | 选型、预算、进入/退出市场、处置风险 |
| `act` | 现在就能执行的具体动作 | 申请、提交、采购、修复、报名 |

### 与现有字段的区别

| 维度 | 问题 | 不因什么而提高 |
|---|---|---|
| `importance` | 事件本身对宏观/行业/技术格局的影响 | 不因读者能否行动而提高 |
| `relevance` | 与读者关注主题的匹配度 | 不因事件重要而提高 |
| `actionability` | 读者是否能据此采取具体动作 | **不因来源权威、事件重要或主题相关而提高** |
| `evidence_completeness` / 证据等级 | 文本能支持到什么程度 | 不因正文较长或来源身份而提高 |

规则写进了 `prompts/analyst.md`（VERSION 4）：例行统计发布且未说明后果的，通常判 `monitor`，
不是 `decide`；只有标题或摘要时，除非文本明确写出下一步，否则不得判 `act` 或 `decide`。

## 二、实现范围

| 层 | 变更 | 兼容性 |
|---|---|---|
| 提示词 | `prompts/analyst.md` 增加字段、枚举与判定规则；版本 3 → 4 | 旧分析记录保留原版本号 |
| 解析器 | `schema.parse_model_json` 校验枚举；缺失 → `actionability=missing`，非法 → `invalid`，**不使分析失败** | 旧模型/旧提示词输出仍可解析 |
| 持久化 | 字段随 `result_json` 一起保存，无 schema 迁移 | 历史记录无此字段，读取方不得假设存在 |
| 报告 | 不展示、不参与排序 | 历史报告重放不受影响（有回归测试） |
| 评分 | **未改动** `scoring.toml`、`evidence.py`、`lanes.py`、`source_cap` | 生产分数与分流不变 |

`actionability_status` 是解析状态（`ok` / `missing` / `invalid`），只供实验统计，不进入评分。

## 四、评估指标

1. **AUC**：`actionability`（0–4 序数）区分「可行动 vs 弱」；对照 `importance` 与总分。
2. **不确定性**：1000 次 bootstrap 的 95% 区间（固定种子 20261023）。
3. **Top-K**：
   - K=13（第二轮 priority 数量）与 K=7（实际展示量）；
   - 分别报告"配额前"（纯排序）与"配额后"（按登记 `source_cap` 逐源截断）的可行动条数。
4. **逐轮与合并**：每轮单独报告，再给合并值；不得只报合并值。
5. **稳定性**：同一 item 在三轮中的 `actionability` 是否一致；分歧条目单列。
6. **失败案例**：`missing` / `invalid` / 分析异常逐条记录。

## 五、判定规则（运行前固定）

| 结论 | 条件 |
|---|---|
| 具备纳入评分的候选资格 | 三轮方向一致，合并 AUC ≥ 0.70，且至少两轮的 95% 区间下界 > 0.5 |
| 继续观察 | AUC 在 0.5–0.7 之间，或轮间方向不一致 |
| 不纳入 | 合并 AUC < 0.5，或三轮均无增益 |

即使满足第一条，本轮也**只**给出"具备进一步评估的条件"，不直接改生产评分；下一轮需独立评审与回归测试。

## 六、禁止事项
