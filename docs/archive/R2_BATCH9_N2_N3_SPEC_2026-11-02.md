## 1. 范围与边界

本批实现：

- **N2：Numeric Candidate Semantic Interpretation**（`opportunity_radar/n2_semantic.py`，`n2-v1`）
- **N3：Numeric Relationship Interpretation**（`opportunity_radar/n3_relationships.py`，`n3-v1`）

本批不实现 N4、N5；不启用 v7；不改变生产分析链路；不申请 G6。

N2/N3 只写入独立的节点留存（`opportunity_radar/pipeline_store.py`）与本批运行目录，
不写入生产 Claim 表、RSS 数据库、SEC/EIA 数据库，不修改 `analyzer.py`、生产提示词、
`claim_contract.py`（r2-v4）、`verify.py`（r2-v2）、`units.py`、评分、门禁、日报与邮件。

## 2. 模型与执行参数

- 本地 llama.cpp server，模型 `Qwen3-30B-A3B-Instruct-2507-Q4_K_M`。
- 复用现有 `LocalAnalyzer`；新增 `complete()` 与可选 `temperature` / `response_format`，
  生产 `analyze()` 的默认调用不变。
- 实际发送：`temperature=0.0`；`response_format={"type":"json_object","schema":...}`
  （llama.cpp 支持；可用 `--no-json-schema` 关闭）；`max_tokens` N2 默认 1600、N3 默认 2400。
- 未发送 `seed`、`top_p`；报告中记录为 `not_sent`，不声称生效。
- 模型指纹：llama.cpp 未提供 GGUF 内容哈希，记录 `model_fingerprint="unknown"`。
- JSON 解析失败最多重试 1 次（要求重排为 JSON），不无限重试。
- 每批候选数默认 4；字符预算 3500；候选所在句完整包含，前后各一句在预算允许时加入。
- 一个候选只属于一个批次；批次不跨 title/body 字段。

## 3. N2 契约

### 3.1 职责

对每个 N1 原子候选回答：它描述什么对象、什么指标、是否构成数值主张，或只是日期/期间/
辅助数字/标识符/无法判断的内容。不重新扫描数字、不计算数值、不判断方向与比较口径、
不生成 Claim。

### 3.2 输入

```json
{"document": "<N0 to_dict()>", "n1": "<N1 output>"}
```

批次上下文由程序构造：候选所在句 + 相邻句，附 `sentence_id` / `paragraph_id`。
模型不接收整篇文章。

### 3.3 输出

```json
{
  "node": "N2", "node_version": "n2-v1", "document_id": "...", "input_hash": "...",
  "prompt_version": "n2-prompt-v1", "prompt_hash": "...",
  "schema_version": "n2-schema-v1", "schema_hash": "...", "ruleset": "...",
  "model": {"provider": "llama.cpp", "model_id": "...", "model_fingerprint": "unknown",
             "generation_params": {"temperature": 0.0, "max_tokens": 1600,
                                   "response_format": "json_schema", "seed": "not_sent",
                                   "top_p": "not_sent"}},
  "candidate_interpretations": [
    {"candidate_id": "...", "disposition": "claim_value", "subject": "...",
     "predicate": "...", "predicate_raw": "...", "predicate_source": "model|subject_fallback",
     "kind": "fact", "reason": "...", "evidence_sentence_ids": ["s0001"],
     "evidence_quote": "...", "evidence_start": 1, "evidence_end": 20,
     "evidence_field": "body", "status": "resolved", "deviations": []}
  ],
  "batches": [{"candidate_ids": [], "status": "success", "attempts": 1,
               "seconds": 0.0, "error": "", "unknown_candidate_ids": [],
               "duplicate_candidate_ids": [], "deviations": []}],
  "statistics": {"input_candidate_count": 0, "resolved_count": 0, "claim_value_count": 0,
                 "claim_value_total": 0, "context_only_count": 0, "non_claim_count": 0,
                 "ambiguous_count": 0, "unresolved_count": 0, "batch_count": 0,
                 "failed_batches": 0, "coverage_complete": true},
  "status": "success|partial|failed|invalid_output|schema_error|model_unavailable|timeout|coverage_error",
  "seconds": 0.0
}
```

`disposition`：`claim_value` / `context_only` / `non_claim` / `ambiguous` / `unresolved`。
`kind`：`fact` / `source_interpretation` / `hypothesis` / `forecast` / `opinion` / `unknown`；
**禁止 `system_inference`**。
`status`：`resolved` / `ambiguous` / `unresolved`。

### 3.4 程序校验

1. 每个输入 `candidate_id` 恰好一个结果；缺失补 `unresolved(model_omitted_candidate)`，
   重复保留第一条并记偏差，额外 ID 丢弃并记录。
2. 枚举非法 → 降级并记录；`claim_value` 缺 subject/predicate、证据缺失或无法定位、
   字段超长 → `status=unresolved`（不静默截断，原文保留 + 偏差）。
3. `evidence_sentence_ids` 必须属于 N0；`evidence_quote` 必须是这些句子范围内的连续原文。
4. `claim_value` 的 `predicate` 若含方向/关系词（increase/decrease/monthly/...）或只是
   `amount/rate/value/level/total`，程序用 subject 的规范化形式替换，原值保存在
   `predicate_raw`，记 `relationship_leak` 偏差。N2 不把关系判断带进指标名。
5. 统计中 `claim_value_count` 只计 `claim_value` 且 `status=resolved`；
   `ambiguous_count` / `unresolved_count` 按 status 计。
6. `status`：全部批次成功且无偏差 → `success`；部分失败/有偏差/覆盖缺口 → `partial`；
   全部批次失败 → 共同的失败状态；无候选 → `success` 且不调用模型。

## 4. N3 契约

### 4.1 职责

读取 N0、N1、N2 成功结果，判断数字之间的关系：水平/变化、方向、同比/环比/月度率/
年度率、期间、比较基准、区间、份额、修订。只对 N2 `claim_value` 且 `status=resolved`
的候选建立数值关系；`context_only` 可作为期间/基准上下文；`non_claim` 不得引用。

### 4.2 输入

```json
{"document": "<N0>", "n1": "<N1>", "n2": "<N2 output>"}
```

N2 `status` 不是 `success`/`partial` 时，N3 返回 `blocked`，不调用模型。
N3 的输入哈希包含 N2 的稳定投影（排除 `seconds`、`batches`），N2 内容变化自动使 N3 失效。

### 4.3 输出

```json
{
  "node": "N3", "node_version": "n3-v1", "document_id": "...", "input_hash": "...",
  "n2_output_hash": "...", "prompt_version": "n3-prompt-v1", "prompt_hash": "...",
  "schema_version": "n3-schema-v1", "schema_hash": "...", "ruleset": "...", "model": {},
  "relationships": [
    {"relationship_id": "r...", "relationship_type": "level", "value_candidate_ids": [],
     "baseline_candidate_ids": [], "period_candidate_ids": [],
     "comparison_period_candidate_ids": [], "denominator_candidate_ids": [],
     "related_expression_ids": [], "direction": "not_applicable", "comparison": "level",
     "seasonality": "unknown", "revision": "unknown", "period_raw": "",
     "evidence_sentence_ids": [], "evidence_quote": "", "evidence_start": 0,
     "evidence_end": 0, "evidence_field": "body", "status": "resolved",
     "reason": "", "deviations": []}
  ],
  "candidate_dispositions": [
    {"candidate_id": "...", "status": "assigned|ambiguous|unresolved",
     "relationship_indexes": [], "reason": "..."}
  ],
  "batches": [], "statistics": {}, "status": "success|partial|failed|blocked|schema_error|model_unavailable|timeout|coverage_error", "seconds": 0.0
}
```

`relationship_type`：`level` / `change` / `comparison` / `range` / `revision` / `share` /
`rate` / `unknown`。
`direction`：`increase` / `decrease` / `unchanged` / `not_applicable` / `unknown`。
`comparison` / `seasonality` / `revision` 严格使用 `claim_contract.py` 的 r2-v4 枚举。

### 4.4 程序校验与确定性守卫

1. 所有候选/表达组 ID 必须存在；`value_candidate_ids` 只能引用本批 N2 `claim_value`；
   baseline/period 只能引用本批窗口内的 `claim_value`/`context_only`；`non_claim` 一律拒绝。
2. `value_candidate_ids` 为空 → 丢弃该关系并记偏差。
3. 枚举非法 → `unknown` + 偏差；证据缺失/无法定位 → 关系 `status=unresolved`。
4. **比较口径守卫**：`monthly_rate` / `annual_rate` / `year_over_year` 等只在原文出现
   对应措辞时接受；措辞必须紧邻该关系的数值候选（40 字符内最近的候选），否则改为
   `unknown`（change）或 `level`（level/rate/share）并记 `attached_to_other_candidate` /
   `not_stated`。`change` 不得使用 `comparison=level`。
5. `period_raw` 必须是上下文中的连续原文，否则清空并记偏差。
6. 每个 N2 `claim_value` 必须得到处置：进入至少一个 resolved 关系（`assigned`），
   或由模型标 `ambiguous`/`unresolved`，或程序补 `unresolved` 并记 `coverage_error`。
7. `relationship_id` 由 n2 稳定哈希、关系类型、value 候选、证据位置决定，不由模型生成。
8. `status`：全部成功且无未处置 → `success`；偏差/未处置/部分失败 → `partial`；
   全部批次失败 → 共同失败状态；无 claim_value → `success` 且不调用模型。

## 5. 留存与缓存

复用 `PipelineStore`，不建第二套存储。每条运行记录 article_id、document_id、content_hash、
node_name、node_version、input_hash、output_hash、execution_status、executed_at、
params_json、tools_json、output_json；`INSERT OR IGNORE`，失败运行带状态标记。

- N2 输入哈希：document_id、text_hash、N1 哈希、节点/Prompt/Schema 版本与哈希、规则源码哈希、模型与参数。
- N3 输入哈希：document_id、text_hash、N1 哈希、N2 稳定哈希、节点/Prompt/Schema 哈希、规则源码哈希、模型与参数。
- 相同输入可复用成功结果；`--no-reuse` 强制重跑；失败记录不阻止后续成功。
- N3 缓存随 N2 内容变化自动失效；时间/重试次数不进入缓存键。

## 6. 工具

- `tools/run_n2_n3.py`：统一入口；`--nodes n2|n3|both`、`--limit`、`--n3-limit`、
  `--fixture`、`--article-id`、`--sources`、`--urls-file`、`--store`、`--no-store`、
  `--no-reuse`、`--no-json-schema`、`--max-candidates`、`--n2-tokens`、`--n3-tokens`、
  `--timeout`。先跑 N2，再对前 N 篇有 claim_value 的文章跑 N3。
- `tools/run_n2.py` / `tools/run_n3.py`：固定 `--nodes` 的薄入口。
- 输出 `n2n3.jsonl`、`summary.json`、`summary.md`；报告模型调用次数、失败、缓存复用、
  节点耗时、关系类型、证据定位率。
- 不写生产库，不改 RSS 日报与生产分析器。

## 7. 验收设计

- 固定样本：BEA 个人收入/贸易/GDP、NYT Intel/Obamacare，以及覆盖百分点、区间、
  from-to、FY、标识符、电话、URL、10-K/8-K、版本号、括号数字、多指标、跨句、无法归属
  主体的合成文章。
- 真实模型：N2、N3 分别实际调用 Qwen3-30B-A3B；保存模型标识、参数、Prompt/Schema 版本、
  调用次数、失败、耗时与程序校验后的结果。
- 关键案例：0.2 percent at a monthly rate、0.5 percent、$92.8bn、$12.8bn、$0.1bn
  的主体与关系。
- 真实语料影子运行：先跑 50 篇代表性文章（N2），N3 按时间/资源跑其中一部分并如实报告；
  不修改生产库。
- 覆盖率与语义准确率分开报告：候选覆盖率不是语义准确率。

## 8. 已知限制

1. 输入仍是标题 + RSS 正文，不是全文。
2. 模型语义判断不是确定性；程序只能保证引用、枚举、覆盖与比较口径的确定性守卫。
3. 比较口径守卫基于措辞与最近候选，无法覆盖所有自然语言变体；无法判断时保留 `unknown`。
4. N1 的括号数字标为 `ambiguous`，N2 可能沿用；N3 不把 ambiguous 当作确认数值。
5. 修订/季节调整只接受原文明确措辞；模型可能漏记，统计中会体现为 `unknown`。
6. N4/N5 未实现：本批不产出 r2-v4 Claim，也不声称完成文章到 Claim 的完整链路。
