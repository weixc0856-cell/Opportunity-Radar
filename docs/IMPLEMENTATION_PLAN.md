## 2. 依赖与顺序

```
R0（完成）──> R1 B1-B4（完成）──> R2 ──> R3 ──> R4
                        │                     ▲
                        └──> R5 ─────────────┘
                                     └──> R6（依赖 R0 的失败分类与 R1 的事件）
S0（完成）──> S1 来源接入（与 R2/R3 并行，受 G5 约束）
```

- R2 依赖 R1 的主张表；R3 依赖 R2 的核验结果；R4 依赖 R1 的事件与 R5 的数据集。
- S1 的接入顺序服从 S0 的缺口优先级：亚洲政策、产业政策、制造/汽车、企业经营、能源。
- 每个阶段必须能独立使用，不以"为下一阶段铺路"作为完成理由。

## 3. 各阶段要点

### R2 主张核验（下一步，需 G6）

- 提示词升级为结构化主张契约（主体/指标/数值/单位/期间/口径），不合规字段降级为偏差记录。
- 建立 `verify.py`：数值语义核验、单位换算表、百分比与百分点区分、期间与口径比对。
- 引文支持关系四分类；同一事件+指标+期间的跨来源冲突检测。
- 未通过核验的主张标记 rejected / unverifiable，不进入"已核验事实"。
- 验收：构造的数值/单位/期间陷阱被拒绝；转载不因数量通过；核验失败不阻断整篇入库。

### R3 编辑与优先级（需 G7）

- 评分拆成 Signal Score（重要性）、Evidence Score（证据强度）、Editorial Priority（编辑排序）。
- 优先级 P0–P3 / REJECT；来源配额与排序解耦；跨期待办与事件新颖性。
- 验收：重要性与证据质量可分别解释；配额只影响分发，不改写结论。

### R4 多周期发布（需 G8）

- 周报/月报从 events、claims、evidences 重新生成，不拼接日报。
- 历史事件时间线、跨期比较、反面证据、数据与图表引用。

### R5 经济数据引擎（需 G8）

- 数据集登记与观测快照；修订不覆盖历史；YoY/MoM/移动平均等计算保留输入与公式。
- 只从已批准的数据集开始，不为数量扩展数据源。

### R6 质量与回测（需 G8）

- 基准样本集（确定性金标、来源锚定、对抗样本、历史案例、未决案例）。
- 自动回归、30/90 天回测、模型与提示词版本对比、来源健康度。
- 无法测量的指标标 NOT_MEASURED。

### S1–S4 来源接入（需 G5）

- S1 连接器框架 + `source_id` 绑定 + 谱系字段；L0/L1 官方源优先（结构化数据）。
- S2 事件发现（GDELT 等公共接口）；S3 学术与技术（OpenAlex、Crossref、arXiv、GitHub）；
  S4 研究机构与专业媒体（官方 RSS 与公开索引，不绕付费墙）。
- 每批开始前完成：条款 URL、许可结论、配额与成本、失败与限速设计、`review_status=approved`。

## 4. 工程约束

- **技术栈**：Python 标准库、SQLite、FreshRSS、llama.cpp、Windows 计划任务。新增依赖需证明必要性
  并记录版本；不引入向量数据库、知识图谱平台或重型编排。
- **迁移**：只追加（CREATE TABLE / ADD COLUMN），`PRAGMA user_version` 版本化；迁移前备份；
  只读路径不迁移。
- **隔离**：SEC/EIA 独立库、独立入口、独立运行记录；共享数据契约，不共享文件。
- **幂等**：内容哈希作为标识；回填与关联命令可重复运行。
- **测试**：单元测试 + 真实数据副本验证 + 端到端故障注入（`tools/e2e_verify.py`）。
  干净检出必须能通过（依赖本地样本的用例显式跳过）。
