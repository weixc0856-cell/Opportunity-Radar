# Opportunity Radar 本地工作台 PRD（建议版）

## 1. 产品概述

**产品名称：** Opportunity Radar  
**定位：** 面向个人开发者、技术顾问与独立创业者的本地机会情报和验证工作台。  
**核心承诺：** 将分散的公开信号整理成可追溯、可复核、可采取下一步行动的研究线索；不承诺自动发现已验证商机。

## 2. 用户与场景

### 目标用户
- 个人开发者/独立创业者：需要从信息噪声中发现可验证的问题。
- 技术型顾问：关注客户问题、竞品和工程工具变化。
- 技术研究者：需要跟踪研究、产品与开发者生态信号。

### 核心场景
1. 管理与审核信息源。
2. 每日自动采集、分析并生成简报。
3. 查看机会线索及证据。
4. 人工复核并记录理由。
5. 查看运行状态、失败原因和邮件投递结果。

## 3. 产品原则

- 证据优先：任何结论都要能回到来源。
- 事实/推断/未知分离。
- 本地优先：默认不把文章内容发往云端模型。
- 最小数据保存：不默认存储未获许可的完整正文。
- 人工最终决策：模型排序不能替代市场访谈。
- 失败可解释：每个失败状态都提供下一步动作。

## 4. MVP 范围

### P0 必须
- 来源列表、编辑、启用/禁用、审核状态、Feed ID 映射。
- 来源审计与错误详情。
- 收件人列表编辑和邮件测试。
- 本地模型健康状态。
- 手动运行日报。
- 每日计划任务注册。
- 报告查看与日志查看。
- 本地 SQLite 数据持久化。
- 安全默认值：loopback only、凭据不展示、来源默认禁用。

### P1 建议
- 运行历史列表：开始时间、结束时间、阶段、耗时、结果、文章数量。
- 邮件逐收件人投递结果。
- 机会线索列表：分类、分数、证据等级、来源、时间、复核状态。
- 机会详情：原文链接、可定位引文、推断、未知项、下一步验证。
- 人工复核：保留原始模型结论、人工结论、修改理由、时间和版本。
- 配置校验页面：显示缺失项，但绝不显示密钥。
- 运行日志下载与脱敏。

### 暂不做
- 公网 SaaS、用户账号、团队协作。
- 自动爬取任意网页或绕过访问限制。
- 多 Agent 自动执行外部动作。
- 自动投资/商业成功预测。
- 未经授权的全文存储和再发布。

## 5. 信息架构

1. 总览
2. 机会线索
3. 信息源
4. 邮件收件人
5. 运行与定时
6. 运行历史
7. 日报与归档
8. 系统设置

## 6. 页面与交互要求

### 总览
显示：本地模型状态、启用来源数、最近运行状态、最近成功报告、收件人数量、最近失败摘要。
- 不显示虚构数据为真实数据。
- 服务未连接时显示“未连接”和排查步骤。

### 信息源
字段至少包括：来源 ID、名称、主页、Feed URL、访问方式、来源类型、证据来源类别、主题、质量层级、条款 URL、Feed 提供方、Feed ID、审核状态、审核日期、最近核验日期、启用状态、备注。
- 未审核来源默认禁用。
- 启用来源前显示检查清单和阻断原因。
- 区分“网络可达”和“许可已审核”。

### 邮件收件人
- 每行一个邮箱，支持添加/删除。
- 保存前校验格式、去重。
- 测试邮件前明确显示目标数量。
- 测试结果按每个地址显示成功/失败；不得把“SMTP 已提交”说成“收件箱已收到”。

### 运行与定时
- 手动运行需确认，运行中禁止重复触发。
- 展示阶段：来源读取、文章入库、模型分析、报告生成、邮件发送。
- 明确“无新内容”“部分成功”“失败”。
- 显示计划任务名称、时间、最近运行结果。

### 机会详情（P1）
固定展示：信号摘要、原始来源、直接证据、模型推断、未知项、付费证据、风险、下一步验证、人工复核。
- 分数旁必须显示解释。
- 高分不等于已验证商机。
- 证据无法定位时显示明确警告。

## 7. 非功能需求

- 本地服务只监听 `127.0.0.1`。
- API 请求体限制大小，字段长度受控。
- 日志不得包含授权码、API Key、完整认证头。
- 写入采用原子替换/事务，并防止并发覆盖。
- SQLite schema 变更必须有迁移测试。
- 所有网络请求有超时。
- 失败可重试，但重试需幂等。
- HTML 输出对不可信文本做转义。
- 桌面与窄屏布局可用；支持键盘操作。
- 报告、邮件和数据库使用同一份结构化分析结果。

## 8. 产品成功指标

早期不以“生成多少条线索”为成功指标，优先看：
- 每周人工复核后保留的线索比例。
- 每条保留线索的证据完整率。
- 用户能够完成下一步验证的比例。
- 每日任务成功率与邮件投递成功率。
- 错误恢复平均耗时。
- 经访谈确认的重复问题数、明确付费意愿数、付费试点数。

这些指标在样本量很小时只能用于内部改进，不应宣传为市场表现。

## 9. 验收标准

- 新来源默认禁用；未批准来源无法启用。
- 多个收件人可以独立投递并返回逐地址结果。
- 本地模型不可用时，任务明确失败且不会伪造分析结果。
- 无新文章时按配置记录 no-new-content，不误报为系统失败。
- 报告写入失败时保留上一份有效报告。
- 重复触发不会并行运行两个完整日报。
- 页面所有操作有加载、成功、错误或空状态。
- 测试覆盖成功、失败、超时、无数据、部分投递和数据库异常。
