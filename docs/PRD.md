# Opportunity Radar 产品需求文档（PRD）

版本：2.0 · 2026-11-01
定位：**产品定义**。写清楚这个产品为谁解决什么问题、有哪些能力、数据长什么样、什么算合格。
不写当前实测数字（见 `PROJECT_STATUS.md`）、不写开发顺序（见 `PROJECT_STATUS.md` 与 `ARCHITECTURE.md`）。

---

## 1. 定位

**全球商业、经济与政策情报 + 商业机会发现 + 技术与产业研究。**

服务对象：

- 企业战略、业务发展、市场研究与企业创新人员；
- 咨询、产业研究与投资研究人员；
- 独立创业者与产品构建者。

默认全球视角，重点关注美国、欧洲、中国及主要亚洲经济体。某一地区更新频繁不等于全球趋势。

**非目标**：RSS 阅读器；新闻搬运或改写；由模型自动撰写的财经文章；预测市场；投资建议。

## 2. 三条研究通道

### A · 商业、经济与政策情报

宏观与货币政策、贸易与地缘经济、产业政策与监管、企业战略与资本开支、行业供需与竞争格局。
每条内容回答：发生了什么、相对历史基线变了什么、为什么重要、影响哪些国家/行业/企业、
有哪些不同解释、哪些数据可以支持或反驳、接下来观察什么。

### B · 商业机会情报

新需求、买方痛点、企业采购、付费行为、供给缺口、商业模式。状态必须逐级有证据：

```
signal_detected → problem_supported → buyer_identified → payment_verified → opportunity_candidate
```

融资额、定价页、访问量、Star 数、厂商宣传都不构成付费证据。交付字段：Problem / Buyer /
Payment / Existing solutions / Market gap / Delivery / Validation。

### C · 技术与工程情报

AI 与软件工程、半导体与算力、数据中心、能源、制造、汽车、工业软件与 CAE、机器人、新材料。
必须区分：论文研究、实验验证、开源实现、工程验证、商业产品、客户部署。技术新颖性不等于商业成熟度。

## 3. 产品形态

| 形态 | 频率 | 回答的问题 | 数据来源 |
|---|---|---|---|
| Daily Brief | 每日 | 今天发生了什么变化 | 当日分析结果；按事件组织，附主张、证据定位与来源画像 |
| Weekly Intelligence | 每周 | 一周内哪些事件发生了变化、彼此有何关系 | 事件与证据表重新生成，不拼接日报 |
| Monthly Research | 每月（有材料时） | 围绕研究问题的完整论证 | 事件、证据、数据集 |
| Opportunity Database | 持续 | 需求、买方、付费证据、缺口的长期沉淀 | B 通道条目与其证据链 |

## 4. 功能需求

### 4.1 来源（S）

- 来源按**用途**分层：L0 原始事实（统计机构、监管、企业公告）→ L1 国际经济机构 → L2 咨询研究 →
  L3 权威新闻 → L4 技术与学术 → L5 早期信号（只作线索）。
- 每个来源登记：访问方式、条款、许可、配额、成本、历史可得性、内容保存与再分发政策、
  来源谱系（所属机构、是否为原始发布方）。
- 未经核验许可的来源保持禁用；正文抓取默认关闭。

### 4.2 运行可靠性（R0）

- 传输失败有界重试；连接级失败后复查模型健康；熔断后剩余条目标记未尝试。
- 运行级覆盖率决定发布状态：PASS / PASS_WITH_LIMITATIONS / HOLD。
- HOLD 不发订阅邮件，保留本地报告与运行记录。
- 明确区分分析失败、投递失败与"没有新内容"。

### 4.3 事件、证据与主张（R1）

| ID | 需求 |
|---|---|
| FR-E1 | 事件实体：一个事件关联多篇文章 |
| FR-E2 | 文章—事件关联记录关系类型与分配方式（规则/人工） |
| FR-E3 | 主张实体：主体、指标、数值、文本、单位、币种、地区、期间、比较口径、分母、季调、修订状态、引文、定位、核验状态 |
| FR-E4 | 主张必须关联可定位的证据；无法定位不得成为已核验主张 |
| FR-E5 | 事件合并/拆分/纠错为追加式记录 |
| FR-E6 | 旧数据回填：可定位事实生成主张；旧格式不伪造主张 |
| FR-E7 | 重复运行不产生重复事件或主张 |
| FR-E8 | 聚类以确定性规则为主，不增加逐篇模型调用 |
| FR-E9 | 独立证据实体：稳定 ID、引文、定位、来源、来源族、独立性；一条证据可支撑多条主张 |

事件合并规则（保守）：规范化 URL 相同，或规范化标题相同且在 72 小时内。其余视为不同事件；
共享关键词不合并。候选关联只记录、不合并。

### 4.4 主张核验（R2）

| ID | 需求 |
|---|---|
| FR-V1 | 提示词升级为结构化主张契约（`prompts/analyst_v7.md`，生产）；不合规字段降级为偏差，不整篇丢弃 |
| FR-V2 | 确定性核验主体、指标、数值、单位、币种、地区、期间、比较口径、分母、季调、修订状态 |
| FR-V3 | 单位换算与百分点/百分比使用显式规则表；数量级（million 等）与物理单位分开存储；约定版本 `r2-v4` |
| FR-V4 | 引文支持关系：直接支持 / 间接支持 / 不支持 / 冲突 |
| FR-V5 | 同一事件+指标+期间的多来源主张冲突检测 |
| FR-V6 | 区分 fact / source_interpretation / system_inference / hypothesis / forecast / opinion |
| FR-V7 | 未通过核验的主张标记 rejected / unverifiable，不得作为已核验事实发布 |
| FR-V8 | 派生数据保留公式、输入、单位与来源 |

### 4.5 编辑与优先级（R3）

评分拆分为 Signal Score、Evidence Score、Editorial Priority；优先级 P0–P3 与 REJECT；
来源配额与编辑排序分离；处理政策事件分类、事件新颖性、反面证据、跨期待办。

### 4.6 多周期发布（R4）

周报与月报从事件、证据、数据集重新生成；历史事件时间线；跨期比较；报告引用数据与图表。

### 4.7 经济数据引擎（R5）

数据集登记（provider、indicator、unit、frequency、geography、seasonal_adjustment、base_period、
revision_policy、license）；观测值历史快照；修订不覆盖历史；派生计算保留输入与公式。

### 4.8 质量与回测（R6）

固定基准样本集（确定性金标、来源锚定、对抗样本、历史案例）；自动回归；30/90 天回测；
模型与提示词版本对比；来源健康度与独立性统计。无法真实测量的指标标 NOT_MEASURED。

## 5. 数据模型

| 实体 | 用途 |
|---|---|
| `articles` / `article_versions` | 文章元数据与内容版本（追加式） |
| `analyses` / `analysis_history` / `analysis_sections` | 结构化分析结果与其历史 |
| `events` / `event_articles` | 事件与文章归属（关系、分配方式、置信度） |
| `evidences` | 证据：引文、定位、来源、来源族、独立性 |
| `claims` / `claim_evidence` | 主张与其证据支撑关系 |
| `entities` / `entity_aliases` / `entity_mentions` | 实体、别名与文本提及 |
| `event_links` | 候选关联（claim↔event、event↔event），状态 candidate/accepted/rejected |
| `event_corrections` | 追加式纠错 |
| `runs` / `deliveries` / `analysis_failures` | 运行、投递与失败记录 |
| SEC/EIA 独立库 | `sec_facts`、`eia_observations` 及其版本与快照 |

约束：标识符为内容哈希，重复运行幂等；迁移只追加；纠错与版本不覆盖历史。

## 6. 质量框架

| 层 | 检查什么 |
|---|---|
| Q1 证据质量 | 主张是否有原文证据、引文是否完整、定位是否有效、来源是否可追溯 |
| Q2 来源独立性 | 来源族、原始/二手、转载关系；多来源验证按**独立来源族**计算，不按文章数 |
| Q3 主张核验 | 主体、指标、数值、单位、期间、口径、分母、季调、修订状态 |
| Q4 分析质量 | 区分事实、来源解释、系统推断、假设、预测、观点；记录支持与反面证据、假设与边界 |
| Q5 发布质量 | 去重、证据完整、数值核验、结构、链接归档、运行完整性 |

发布状态：`PASS` / `PASS_WITH_LIMITATIONS`（披露覆盖率与失败原因）/ `HOLD`（不发订阅邮件）/
`REJECT`（不进入本期）。

独立佐证的定义：**至少两个来源族，且这些族有已记录的独立性判断**。同一机构的多个栏目算一个族；
共享联合发布组的不同机构算一个单元；未知来源不计入。

## 7. 指标

| 指标 | 可测量性 |
|---|---|
| 引文定位率、证据覆盖率、数值/单位/期间一致性 | 有确定性基准时可测 |
| 事件聚类 precision / recall | 需要标注基准；当前只能给待建立状态 |
| 独立来源覆盖率 | 依赖来源谱系完整度，未登记来源不计 |
| 发布门禁逃逸率、运行失败率 | 可从运行记录直接统计 |
| 来源产出与证据通过率 | 可从数据库统计 |

无法真实测量的指标标 `NOT_MEASURED`，不得用模型自评填充。

## 8. 约束

- 本地优先：SQLite + FreshRSS + llama.cpp + Windows 计划任务；不引入向量库、知识图谱平台或
  重型编排框架，除非基准证明现有方案不足。
- 模型只做初筛；营收、市场规模、法律结论必须核对原始来源。
- 邮件只含摘要与原始链接，不复制全文。
- 人工复核保留但不作为日常运行的前置条件，也不作为阶段验收指标。
