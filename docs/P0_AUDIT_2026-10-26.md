## 二、四个问题的结论

### 1. 分类枚举与分析失败

- 枚举白名单在 `schema.py:2`，非法值在 `schema.py:52` 硬失败；下游 `classifier` / `lanes` 只做
  字符串比较，存储是 JSON，不存枚举列，因此**只有解析层是硬门槛**。
- `policy_change` / `political_event` 三轮稳定失败（2/28），重试只要求"重排格式"，不会纠正取值。
- 运行级区分（`analysis_failed` vs `no_new_content`）正确，但发现三处会把失败说成"空"：
  - 执行摘要先判断 `skipped`、后判断 `failed`（`digest.py:74`），归档报告
    `reports/archive/2026/10/23/2026-10-23-104212.txt` 即是实例；
  - `--dry-run` 固定 `dry_run` / 退出码 0（`cli.py:382`），run 3 是 0 成功、5 失败、退出码 0；
  - 失败明细只进滚动日志，`analyses.status` 恒为 `'ok'`，库里无法复查失败文章。

### 2. actionability AUC 0.388

- 重算：0.394 / 0.394 / 0.365（合并 0.388 按条目聚合；未聚合池化 0.384）。
- `auc()` 方向正确，`actionability` 不参与评分，无符号反转、无目标泄漏。
- 机制：78 次输出没有 `decide`/`act`；可行动组均值 1.40、弱组 1.61，在 monitor/investigate
  边界上轻微反向。把 `noise` 计入负样本后 AUC 为 0.443，仍低于 0.5。
- **新发现**：盲评文件里的摘要取自模型的 `summary_zh`（`tools/blind_review.py:37`），不是原文。
  标签与模型输出同源。这是评测有效性问题，不是本字段的代码 bug；第四阶段建立标注集前必须改。

### 3. source_cap

- 超额条目只改 `distribution='deferred'`，`status`/分数/证据保留，本期附录可见；没有把 priority
  改写成 filtered。
- **没有"下一期"**：次日运行只分析当轮采到且未分析过的文章，deferred 条目不会重新进入候选；
  `--render-only` 会把最近 500 条重新套用同一配额。数据在库里，但条目不会再出现在后续阅读区。
- 第二轮候选组 28 条中 17 条 deferred，其中 9 条是 priority（5 条分数 80–81）。

### 4. 证据定位

- 归一化子串定位有效；任一引文无法定位即 `unlocated_quotes` → E0 → 强制过滤，编造引文不能晋升。
- 弱点：
  - 没有最小信息量门槛；生产库有 `"Points: 1"`、`"# Comments: 0"`、`"SCNR."` 这类"已定位引文"，
    并让 `corroboration` 拿到 3 分；
  - `content_basis` 只看来源声明，不看本篇 `retrieval_status`；声明 `full_text` 后抓取失败仍按 E2 计；
  - 定位只证明文本存在，不证明它支持所附主张；偏移基于归一化文本，不能回切原文；
  - 归档不保存原文，事后无法独立复核。
