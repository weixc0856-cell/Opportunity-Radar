# 正文完整性抽样（2026-10-23）

> 对象：NVIDIA Newsroom、UK ONS、Federal Reserve。每源 3 篇，按 Feed 摘要长度取 25/50/75 分位。
> 只读：经 robots 检查后取一次页面，不保存正文，不写数据库，不修改登记。
> **技术通过不等于获准启用**：许可仍未阅读，三个来源的 `full_text_fetch` 保持 `none`。

## 一、判定标准（运行前固定）

每源 3 篇，同时满足才算技术通过：

1. 3/3 抓取成功（无 robots 拒绝、401/403/429、跨域跳转）；
2. ≥2/3 的提取容器为 `article` / `main` / `content-div`；
3. ≥2/3 的 Feed 摘要窗口命中 ≥3/5（摘要确属该页内容）；
4. ≥2/3 的页面正文 ≥ max(600 字符, 1.5 × Feed 摘要)；
5. ≥2/3 的标题出现在页面中；
6. 0 篇命中付费墙/JS 空页。

技术通过之外还有独立的许可门：必须阅读条款并确认允许自动获取与保存，才允许把 `full_text_fetch` 改为 `article_page`；之后还要复核正文完整性，才能声明 `content_access_level=full_text`。本轮**没有越过任何一道门**。

## 三、方法修正（如实记录）

首次运行时 NVIDIA 判为不通过，原因是标题检查只在**提取出的正文**里找标题，而页面的 `<h1>` 位于 `<article>` 之外。
改为在**整页文本**中检查标题后，NVIDIA 3/3 命中。这是检查方法的错误，不是来源失败；修正已写入审计工具，
其余标准未变。

## 四、解读与限制

- 三个来源的页面正文都显著长于 Feed 摘要，Feed 摘要确实来自同一篇内容（窗口命中）。
- **NVIDIA 第 3 篇**落到 `body` 容器，16k 字符里混有导航与推荐位；说明该来源的页面模板并不统一。
  即使启用，也需要正文去噪或人工复核，不能直接当全文。
- **ONS 与 Fed 页面没有可解析的发布日期元数据**，只能以 Feed 的 `pubDate` 为准；这削弱了“页面与条目是同一发布”的交叉验证。
- 每源只有 3 篇、单次抓取；没有覆盖 JS 渲染页、分页、付费墙变体，也没有测长期稳定性。
- 许可状态仍为 unknown：NVIDIA 是厂商站点，ONS/Fed 是政府统计机构，但**来源身份不构成许可**。
